Reads like less

It never loads the file.

less-sheet maps the file and parses only the rows in view, so opening is measured in milliseconds regardless of size and memory stays flat while you scroll through gigabytes.

Jump to any row — including row 100,000,000 — and it lands there without reading what came before. Anything that isn't instant shows progress and can be cancelled. Nothing blocks the window.

Point it at an HTTP(S) URL and it behaves the same way: only the bytes you actually look at are ever fetched.

Guessed, then yours

Change how it's parsed without reopening it.

Separator, quote character, header row and text encoding are detected from the file itself — open and read, no import dialog.

When the guess is wrong, every one of those is a live control: change it and the open document re-renders. No closing the file, no re-importing, no starting again.

Find · filter · jump

Search a file you can't open elsewhere.

Incremental search with live match counts, typed column predicates (qty ≤ 2), and filtered views that keep the original row numbers so you always know where you are in the real file.

Copy returns the original values — not what the screen happens to be formatting.

Why a spreadsheet struggles with this.

Nothing here is a knock on spreadsheets — they're built to edit and compute. That design costs them the things a viewer needs.

less-sheet is read-only by design. Formatting is a display transform over untouched bytes, so what you see never becomes what your file contains.
